## Task 3 - wolf-debug chip v2 (prototype/js/wolf-debug.js)
The file is still inert unless `?whdbg=1`. It keeps the same 500 ms interval, inline styles, `#wh-hud` mount, 2-wolf cap and all existing fields. It changes zero game logic: it only reads values. These guarded, read-only helpers were added:
- `actW` returns the effective weight if the action is running, otherwise 0, inside a try block.
- `wOf` reads W(Hit) / W(Death) from `anim.actions['WH_Wolf_Hit' | 'WH_Wolf_Death']`.
- `top2` returns the 2 highest-weighted actions (the `WH_Wolf_` prefix is stripped, weights below 0.01 are skipped).
- `standIn` traverses `e.body` and returns the first name matching /standin/i.
- `clipCount` reads `WH_ASSETS.getClips(WH_CONFIG.assets.bodyByType.wolf || 'wolfBody').length`.
- `tailLines` builds the `CLIPS=n` / `rigid=` / `standin=` line, plus `STAND-IN IN PLAY: <name>`.
- The new `mts=` field shows `mixer.timeScale`.
- `getState()` is now wrapped in try. Null enemies and missing lists are skipped.
- The NO ANIM OBJ branch now also prints CLIPS and stand-in detection.

The mock also ran a hostile case: getState throws, traverse throws, a bare `{}` action and a null enemy. The chip printed `?` and `none` and did not throw.
How to read it:
- `mts=0.00` means the mixer is frozen.
- `W(walk)=1.00` with legs that don't move, plus `top=Walk:1.00/...`, points at the rig or bind, not the blend.
- A `top=Hit:..` or `W(Death)>0` on a live chasing wolf means a stuck one-shot.
- `rigid=yes` on a wolf means it took the unrigged path.
